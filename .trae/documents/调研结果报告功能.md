# 调研结果报告功能实现计划

## Summary

在 survey.html 中新增一个公开的"调研结果"页面，按报告模板的章节结构，以图表卡片形式展示调研数据分析结果。该页面**不需要密码**，所有用户均可查看。Header 右侧新增"调研结果"按钮（与现有"查看统计结果"按钮并列），点击后进入报告页。

## Current State Analysis

- 当前有 7 个页面：Landing、Name、Survey、Thankyou、End、AdminLogin、Stats
- Header 右侧已有"查看统计结果"按钮（需密码）
- 现有统计面板（pageStats）是逐题平铺的条形图，无章节分组、无交叉分析、无结论计算
- 数据来源：`/api/stats`（需 token），或 fallback localStorage
- 报告模板共 7 章 + 附录，需要的数据分析包括：分布统计、交叉对比、解禁可行性指数计算

### 4. 数据获取方式

"调研结果"页面是公开的，不需要 token。数据获取方式：

**方案**：在现有 `/api/stats` 之外新增 `/api/report` 接口（不需要 token 验证），返回与 `/api/stats` 相同的数据。或者更简单：**前端直接调用 `/api/submit` 只写不改的 GET 逻辑** —— 但现有 `/api/stats` 需要 token。

**最终决定**：在前端直接尝试 GET `/api/stats`（不带 token），如果 401 则 fallback 到 localStorage。但更合理的做法是：让"调研结果"页面用**管理员 token**（如果用户之前登录过），否则 fallback。这样最简单，不需要新增后端接口。

**实际方案**：
```javascript
async function loadAndRenderReport() {
  showToast('正在加载调研报告...');
  try {
    // 尝试用已有 token 获取
    const headers = {};
    if (adminToken) headers['X-Admin-Token'] = adminToken;
    const res = await fetch(`${API_BASE}/stats`, { headers });
    if (res.ok) {
      const data = await res.json();
      if (data.success) { renderReportWithData(data.data); return; }
    }
  } catch(e) {}
  // Fallback to localStorage
  const local = localStorage.getItem('gz_ebike_survey_data');
  renderReportWithData(local ? [JSON.parse(local)] : []);
}
```

## Assumptions & Decisions

1. **不需要新后端接口**：复用 `/api/stats`，无 token 时 fallback localStorage
2. **不需要图表库**：全部用 HTML + CSS 实现（条形图、百分比、大数字），保持零依赖
3. **不修改报告模板文件**：模板是参考文档，不是代码
4. **雷达图用简化方式实现**：用 4 个进度条代替 SVG 雷达图（保持简单）
5. **交叉分析只做车主 vs 非车主**：按 Q2 的答案分组，对比 Q12、Q16 的分布
6. **可行性指数算法**：按模板定义的权重计算，结果映射到结论文字
7. **同名文件同步**：survey.html 修改后同步到 index.html
